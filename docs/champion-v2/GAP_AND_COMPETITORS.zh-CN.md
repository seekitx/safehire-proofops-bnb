# 四维差距与竞争策略

研究基线：feature 分支 `447095f7`；研究版本日期 2026-09-06。以下将官方事实、公开项目自述、代码检查和我的判断分开。没有拿到完整官方参赛名单，也没有其他团队的私有代码，不能给出可信的夺冠概率或实力排名。

## 1. 业务能力：缺的不是更多按钮，而是可重复成交和交付

检查基线 `decision/market.py`：`verified_paid_outcomes=None`、报价要求重新协商、`execution_hire_available=False`；比较只返回证据，没有经过配对交付验证的质量赢家。`live_agent_market.py` 与 `live_erc8183.py` 的有效主路径仍围绕已经审核的 Brain 服务。四个技能不等于四个独立经营主体。代码这样披露比虚构“已证明收益”正确，但商业闭环尚未完成。

| 基线差距 | 本轮实际补强 | 仍不能声称完成 |
|---|---|---|
| 只有分类/注册证据，缺统一任务验收 | `TaskSpec` 固定分类、快照、TTL、预算；域分离任务 hash；四类输出验收 | 输入快照的链上真实性；策略未来有效性 |
| 同类比较缺共同输入与原始输出 | 两至三个不同 agent_ref，对同一任务重算；保留 exact output | 不同标签等于独立企业；人工质量优胜者 |
| 供应商接入耦合现有服务 | 可配置 `56:token_id:skill_id` 路由；两类报价适配器；失败不换供应商 | 自动开放上架、供应商身份认证、第二家真实业务接入 |
| 验收原文和页面状态无法长期对照 | SQLite WAL、任务 capability、幂等、版本号、完整性导出 | 钱包身份认证、多租户计费、不可回滚数据库 |
| LP 重平衡容易混成资产权重调整 | tick 对齐、区间移出判断、定 L 理论库存与差额 | 池子真实性、NFT 权属、swap/撤仓/mint 交易 |
| 单纯收益计算没有“什么也不做”基线 | 收益与保留当前仓位比较；计成本、容量与退出等待 | 实时 APR/APY 数据、未来收益保证 |

**判断：V2 将你从“证据目录”往“可以验收的采购过程”推进，但还不是已经打通的双边市场。** 真实商户和真实交付是下一步最高优先级，不应继续用本地 agent 数量替代。

## 2. 创新：协议拼接不应当成为主卖点

建议主叙事：**“金融 Agent 的任务验收市场：先约定什么算完成，再雇佣，再核验。”**

本轮形成三个可演示的机制：

1. 同一输入、同一快照、同一约束的任务标识，阻止拿另一个任务的结果来通过验收；风险输入发生变化，旧方案不能继续沿用。
2. 金融语义的确定性重算。不是问 LLM “这个结果靠谱吗”，而是核对 tick、成本、容量、偿债预算和压力后的目标。
3. 导出精确原文、报告与本地事件 hash 链。第三方可复核记录一致性，同时清楚知道它不是签名、公链证明或收益证明。

这是一种产品组合上的差异化建议，**没有证据证明全球首创或构成专利新颖性**。代码本身也没有用零知识证明、TEE 或任意合约审计来粉饰可信度。

尚缺的更强创新层应围绕同一商业问题，而不是扩展成第五赛道：供应商签署任务/报价/交付，真正的付费后服务质量记录，以及按可比较样本展示失败率和兑现情况。当前 V2 的 `winner=null` 是有意保留：约束通过不等于质量最好。

## 3. 评委：官方需要可用市场，而不是单独的安全控制台

官方主赛明确关注 Functionality、Data Quality、Agent Diversity；四类要求同等深度；前台应让没有 Agent Studio 知识的人完成发现、理解与激活；展示的 Agent 必须在 BSC 上真实可用。[S1]

因此优先级是：**不破坏你已经提交的入口 → 看懂服务与限制 → 真实报价和雇佣 → 真交付 → 真验收 → 能再次选择。** Arena 是这个路径的补充，不能把所有用户都强迫带到高级 JSON 控制台。

本轮加了四类一键合成引导，不需要编辑 JSON；但不能用它替代真实雇佣。公开部署时首页仍应以 market 的发现/雇佣为主，Arena 用于说明选择依据和交付验收。

注意官方材料有口径差异：博客把四类作为能力覆盖参考，活动主页面则明确要求四类同等深度。本方案按更严格的主页面准备，不自行编造评分权重。第二阶段具体标准在主页面仍未披露；不能声称“已经完全匹配冠军评分公式”。[S1][S2]

TermiX 是独立赛道，其页面要求至少三个真实任务、Agent 与不用 Agent 双路径、实际输出/时间/成本/质量，并说明会亲自雇佣测试。**合成 walkthrough、单元测试和修改字段得到的反例均不满足真实任务要求。** [S3]

## 4. 面向竞争对手：借鉴强项，不制造虚假领先

| 项目与本轮证据 | 可借鉴强项 | 你目前的竞争缺口 | 本轮策略 |
|---|---|---|---|
| HIREDESK：项目 README，自述针对本届；查到两分钟引导、四类服务、限额/白名单/期限/撤销；本轮未重放其链上执行 [S4] | 入门快、安全权限直观 | 单靠“权限隔离＋四分类”缺少辨识度 | 展示具体错误方案为何失败，保留你原权限雇佣链路；不宣称它没有安全能力 |
| minia2a：其自有 pitch deck；发现→试用→付费、开放上架；规模数字为其自报，未独立验证 [S5] | 供给增长、低摩擦试用、开放商业模式 | 真实供给太集中、供应商接入不够产品化 | 优先少量真实可验收金融服务，补可配置适配层；不与未核验调用量竞赛 |
| SmartSentinels：其 Hub 声称 Marketplace/Labs/Prediction 等模块，创始人公开发文参赛；一个 marketplace 文档地址本轮返回404 [S6][S7] | 展示的是完整生态叙事 | 你需说明用户何时会付费，不能只证明技术模块存在 | 聚焦一笔金融任务的采购与验收。页面证据不足以评估其完整代码/安全/交易实力 |

minia2a 文档把 Base 上支付和后续 BSC/身份集成分开描述；这只说明所读文档的范围，不足以断言其当前没有 BSC 成果。SmartSentinels 的动态界面抓取很少，不能据此给它低分。[S5][S6]

## 5. 最应该投入的下一步

| 顺序 | 交付目标 | 冠军竞争力上的意义 | 不可替代的验收 |
|---|---|---|---|
| P0-1 | 第二家真实供应商，至少在一个类别形成真实可比选择 | 证明市场而不是自营工具菜单 | 身份、技能、报价、原始交付；披露同一运营方/利益关系 |
| P0-2 | 选一个真实金融任务贯穿发现、手动付款、交付、任务验收 | 证明用户能买到成果 | 任务标识与链上 job 和 exact bytes 的认证绑定 |
| P0-3 | 四类实际能力和所展示承诺对齐 | 防止分类覆盖只停在文案 | 分析/计划/执行明确分层；LP 不能用组合权重调整冒充 |
| P0-4 | 提交入口、部署版本、视频与真实证据一致 | 让评委能复现而不是听解释 | 外部无账号或最少步骤的可用路径；期间持续可达 |
| P1 | 独立评测与结果回灌 | 形成累积数据价值 | 至少三对真实任务；原文、计时、成本、身份及利益关系 |

不建议截止前把合约支付层整体重写、增加自己的代币、跨到新链，或凭空加入自动交易托管。这些会增加未验证面，不直接解决上述缺口。
