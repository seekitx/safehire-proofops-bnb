# 业务可信边界补强 — 2026-09-07

本轮代码未进行构建或运行测试；新增回归用例等待执行。不会自动部署绿云。

## 行为变化

1. 通用模拟必须严格 `passed: true`；失败、字符串、数字和缺字段均拒绝。
   服务端保存原请求 hash、policy ID 和五分钟有效期，执行时重查。
   旧记录没有这些绑定会被拒绝，需新建并重新模拟。
2. 通用模拟仍是调用方声明，因此仅能用于演示。通用真实执行在发送前阻止；
   不能靠启用环境开关绕过可信模拟器缺失。独立 `/hire-live` 钱包路径保留。
3. RemoteAgentExecutionAdapter 没有服务端注入的可信回执核验器就不发送请求。
   只有核验器返回严格 true 才能标记链上成功。当前生产 bootstrap 不注入核验器。
   这是关闭不可信通道，不是声称通用交易核验已完整实现。
4. 新增私有任务 `POST /api/arena/tasks/{id}/delivery-acceptance`，请求
   `{"job_id":123,"agent_ref":"56:token:skill"}`，沿用 task Bearer token。
   从原有 live_delivery 读取并核对链上承诺的真实内容，再按冻结任务重新验收。
   页面可查看和导出结果，不自动写入信誉、付款统计或结算。

## 签名任务绑定协议复核

`POST /api/live-hire/prepare` 新增可选 `arena_task`，内容为完整规范化 TaskSpec。
沿用现有签名域、金额、合约、服务参数和钱包确认步骤。该字段进入 task_description，
由原签名报价核验器检查供应商是否签了完整请求；供应商若丢字段，拒绝而非兼容降级。
读取任务时保留该字段，验收比较规范化任务 hash、快照 hash、身份＋技能＋类别。
没有 arena_task 的历史交付不能通过此验收桥，但原有雇佣/查看交付不受影响。

供应商需读取完整 arena_task 并将 `safehire-proposal/2` JSON 原文放入交付 manifest 的
response.content。当前供应商是否支持这一输出契约尚未实测；不能声称已经完成真实联调。
现有 task_input 仍按原规则验证，不把 Arena LP 输入冒充组合权重调整指令。
准备报价者应同时提供原服务所需 task_input 和冻结 arena_task；二者的业务语义兼容性
仍需按供应商适配复核。本轮不修改供应商程序，不广播交易。

## 数据源与验收边界

桥接器读取 BSC 链 ID、规范区块 hash、区块时间和该块 ERC-8004 钱包归属，结束前重查
区块是否改变。它只认证区块和身份，金融输入（APR、仓位、成本等）仍为 caller supplied。
不是四类完整可信行情适配器，也不是防重组的轻客户端证明。任务或区块过期会拒绝当前
验收；耗时任务需要在雇佣前制定合理有效期，不能事后改时间来让旧交付通过。
约束通过不等于工作质量认证、支付证明、实际执行或盈利。结算继续由用户人工决定。
